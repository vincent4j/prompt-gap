# M2 验收：先可靠留档，再按需查看

2026-09-16 · M1 已验收；M2（阶段 2＋3）已实现，等待本轮验收。

## 你现在只需要确认什么

这一版解决的是：**以后想复盘时，有当时留下的需求、理解、实际请求和结果可读，而不是靠事后回忆。**

选择 PromptGap 后按数字操作：尚未启用时可开启；启用后可查看最近任务、选择历史任务或关闭。历史列表显示名称、日期、生成次数和反馈摘要，五条一页；不用输入路径或任务 ID。M2 展示过程记录，M3 才把它们整理为你已认可的 report/details 审核报告。

## 验证结果

- **通过**：26 项自动化测试（M1 5 项＋M2 21 项），包含 12 次并发 begin，全部通过。
- **通过**：离线通用 API 接入演示实际落盘并执行完整性检查，issues 为空。使用合成样例，没有调用模型。
- **通过**：官方 Skill 格式检查 `Skill is valid!`。检查器需要 PyYAML，通过临时工具环境运行；记录器本身不需要该依赖。
- **未验证**：Codex 中 `/P` 的真实自动补全、内置真实图片返回和不同 API 真实调用；留给 M4，不能拿合成测试冒充成功。
- **不适用本轮**：自动诊断、report/details 自动生成、模型能力调研（M3）。

## 会不会拖慢生图

记录器不新增模型调用，不把整份日志返回对话；相同素材只保留一份。菜单读取小型索引，不打开所有图片。

本机临时目录测试：每组 6 次 begin＋finish。1 KB 合成文件首次约 47.74 ms，后续中位数约 2.91 ms；8 MiB 合成文件首次约 17.03 ms，后续中位数约 16.79 ms。首组包含可选图片元数据模块首次加载。

**这只测本地文件留档，不是整体生图增时。**没有计入 Agent 整理需求、工具往返、网络下载或真实高分辨率图片检查；Token 也未取得可核算账单，不能宣称零消耗。真实端到端开销在 M4 测。当前索引更新会读取任务元数据，极大量历史的性能尚未验证。

## 必须知道的边界

1. “自动”是 Agent 按项目规则执行，不是系统级拦截。完全绕开规则的调用无法被检测；入口初始标为未验证覆盖。
2. 内置工具隐藏的模型版本、内部提示词或素材路径不会猜补。补录明确标为补录，不能冒充当时事实。
3. 日志只做尽力脱敏，未知供应商的特殊凭据仍需调用方主动排除；Git 忽略规则不会让已跟踪文件自动退出版本管理。
4. 哈希用于一致性检查，不是安全防篡改证明。跨文件写入不是数据库事务；中断可留下待恢复记录，不自动删除证据。
5. 本轮未安装到全局或启用 Poster Fit，未改既有生图脚本，未付费生成，未提交或推送。
