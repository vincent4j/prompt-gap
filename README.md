<a id="为什么需要-promptgap"></a>

## 💡 为什么需要 PromptGap？

你用 AI 生成图片时，是不是也遇到过这些问题？

- **改了两三次，还是不对，却不知道该改什么。** 需求讲过了，AI 也说理解了，但图片仍不符合预期。该重新描述需求、调整提示词，还是换模型？
- **想看实际传给模型的内容，得到的却只有一句概括。** 到底用了哪些参考图、发了什么完整提示词、设置了什么参数？缺了这些，就很难判断偏差从哪里开始。
- **事后复盘，过程已经找不全了。** 几轮尝试之后，当时的理解、输入图片和模型原始返回混在聊天里，复盘容易变成凭印象解释。
- **这次图片很好，也想知道它是怎么做出来的。** 不一定要出了问题才值得查看过程。成功时，你也应该能看懂需求如何变成实际输入，再得到结果。

**反复试错之前，先把“哪里出了偏差”看清楚。**

PromptGap 是一个提示词审核 Skill：项目开启留档后，由 Agent 在生图前后保存可见事实；当你想了解过程或排查问题时，再选择任务，生成完整审核报告。

它不替你生图，也不替换已有工具。当前面向 **文生图和图生图，同时覆盖 Codex 内置生图与 API 调用的留档**。

### ✅ 在你用之前，你可能想知道

| 你的疑问 | PromptGap 的做法 |
|---|---|
| ⚡ 会拖慢生图、增加 Token 吗？ | 平时只留事实，不每次生成长报告，也不额外调用评审模型。主动审核才看图分析；不承诺零开销，总体时间和 Token 开销仍需持续验证。 |
| 📝 要自己维护日志吗？ | 不需要手写日志。启用后由 Agent 按项目规则记录；你通过数字菜单操作。 |
| 🧩 换了 API 还能用吗？ | 保存每次实际可见的请求、响应和素材，不绑定供应商名单。新入口仍需由调用方接入留档步骤，不是自动拦截任何 API。 |
| 🔐 图片和提示词会被上传吗？ | 记录器只在本地保存，不额外上传。你原本使用的生图工具/API 仍按自身规则处理输入；分享报告前应检查隐私。 |
| 🔍 能直接证明模型没能力吗？ | 不能凭一次失败下结论。先定位本次偏差；你明确选择后，才进一步调研模型能力及专业测评。 |

## 🎯 能帮你做什么？

| 你想解决的问题 | PromptGap 怎么处理 | 你得到什么 |
|---|---|---|
| 生成多次仍不符合预期 | 对照需求、当时理解、实际请求和原始结果，逐次核对 | 偏差出现在哪一层、依据是什么、下一步该调整什么 |
| 看懂一次成功生成 | 同样展示完整过程，不只写“通过” | 用过的参考图、完整提示词、参数、返回和检查过程 |
| 图生图改对了目标，却改坏其他部分 | 分别检查“要改什么”和“必须保留什么” | 不把“改色成功”当成“其余细节也保留成功” |
| 想查看以前的某个任务 | 按标题、时间、调用次数和反馈摘要列出历史，按编号选择 | 不用记住路径或任务 ID，也不用跨项目翻日志 |
| 怀疑模型能力不匹配 | 经你选择后，再查相关能力证据并说明适用范围 | 判断继续优化提示词、考虑换模型，还是证据尚不足 |

<a id="三层偏差分析"></a>

### 🧭 三层偏差分析

**先确认你要什么，再看 AI 怎样理解、怎样表达，最后看模型做到了什么。**

| 层次 | 核对什么 | 可能发现的问题 |
|---|---|---|
| ① 需求理解 | 用户原话与 Agent 当时的理解 | 你只要求换背景，Agent 却把重做服装也当成了目标 |
| ② 提示词覆盖 | 理解与实际发送的提示词、图片、参数 | 理解中要求保留纽扣，实际请求却漏掉约束或相关参考图 |
| ③ 模型执行 | 实际请求与原始生成结果 | 请求已经写清且输入可追溯，结果仍改变了纽扣位置 |

以上是说明性例子，不是对某个模型的能力结论。同一个问题可以涉及多层；记录缺失时写明无法确定，不把推测包装成根因。

例如“只把红杯改成蓝色，其他部分保持不变”：即使杯子变蓝，只要形状或细节发生偏移，报告也要分别说明改色与保留的结果，而不是笼统判定成功。

<a id="快速上手"></a>

## 🚀 快速上手

### 1. 安装一次

一条命令安装，也可以复制给 Agent 执行：

```bash
npx skills add vincent4j/prompt-gap
```

按提示选择 Codex 和安装范围；已有同名安装时先确认再更新。安装命令需要 Node.js/npm；Skill 运行需要 Python 3.10+，核心无额外第三方依赖，Pillow 仅用于补充部分图片元数据。更多选项见 [安装与使用](docs/安装与使用.md)。

### 2. 选择 Skill，按数字操作

在支持 Skill 斜杠选择的 Codex 输入框里输入 `/p`，从候选列表选择 **PromptGap** 并发送。这是客户端已有的 Skill 选择入口，不需要记住一套命令。

首次使用一个尚未开启留档的项目时，你会看到类似菜单：

```text
当前项目尚未开启留档。

1. 启用本项目自动留档
2. 从现有上下文补录
3. 查看使用说明
0. 退出

回复数字即可。
```

选择启用后，Agent 会在当前项目的 `AGENTS.md` 添加短规则，配置本地留档目录和 Git 忽略项。**安装一次，各项目分别启用；不会自动给其他项目开启留档。**

已经启用且有记录时，菜单会提供最近任务报告、历史任务选择和关闭选项；关闭后可以恢复，历史不会删除。不需要重复安装。

> 留档由 Agent 遵守项目规则执行，不是后台拦截器。首次启用不会自动补齐过去记录；补录只能保存现有证据，不能还原缺失事实。客户端候选显示取决于宿主加载，安装后的实际发现仍需确认。

### 3. 正常生图，需要时再看报告

继续使用你原本的内置生图工具或 API。项目启用后，Agent 在调用前保存相关需求、理解和实际输入，返回后保存结果或错误。

你想复盘或了解过程时，再选择 PromptGap，按菜单选一个任务即可。无需记住“复盘最近三次生成”这样的指令，也不要求每次生图后阅读报告。

<a id="报告怎么看"></a>

## 📖 报告怎么看？

**先打开 `report.md`，按第一次、第二次、第三次执行依次阅读。** 这是完整报告，不是一个让你继续翻文件找上下文的摘要。

每次执行都说清楚：

1. **本次完成情况或具体问题**——哪里符合，哪里不符合。
2. **用户要求什么**——原话、继承要求，以及哪些内容其实是 Agent 自选的。
3. **AI 当时怎样理解**——生成前留下的理解，不是事后补写的解释。
4. **实际传给模型什么**——完整提示词、输入图片及职责、可见参数。
5. **模型实际返回什么**——原图、可见响应或错误；当时自检与用户反馈单独呈现。
6. **审核结论是什么**——逐项比较三层证据，说明本轮解决、新增、未解决的问题、风险和下一步。

成功与失败使用同一完整模板。缺失的字段明确标注，不要求你先读底层 JSON 才能看懂。

👉 [查看完整成功报告样例](examples/generated-success-complete/report.md)

样例使用合成素材，用来展示阅读方式，不构成真实模型能力证据。`details.md` 保留逐次详情入口，日常阅读主报告即可。

<a id="设计理念"></a>

## 🧩 设计理念

**平时留下事实，需要时再分析；让每一个结论都能回到当时的输入与输出。**

- **先有需求，再审核提示词。** 不从提示词倒推用户想要什么，也不把 Agent 自加的要求说成用户要求。
- **记录与分析分开。** 留档不等于每次全面审核，避免为了极少数复盘打断所有生成任务。
- **保留历史，不改写过去。** 用户纠正后追加反馈、生成新审核版本，旧请求和旧报告仍保留。
- **只解释能看到的过程。** 不宣称揭示模型内部思维；隐藏模型版本、费用和内部改写不可见时明确说明。
- **不绑定项目或供应商。** 商品规则属于使用项目；鉴权、生成、轮询和下载属于已有工具，PromptGap 负责事实记录与审核。
- **不擅自继续花钱。** 查看报告不等于授权重新生图、自动换模型或联网研究。记录失败也不能成为重复提交生成的理由。

## 📦 当前范围与开发资料

当前支持文生图、图生图的本地留档与按需审核；视频和文字生成审核尚未实现。内置工具与 Sunburst API 各一次生成、一次编辑的真实留档及完整报告已验证，报告获用户验收；这不等于所有供应商、异步生产入口或未来调用都已覆盖。

核心记录器和审核报告有自动化回归测试。客户端候选发现仍待用户验收，总体时间与 Token 开销仅部分验证。
